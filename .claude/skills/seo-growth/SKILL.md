# SEO + growth operating method

Read `seo/CONTEXT.md` before changing public discoverability.

## Start from pain, not keywords

1. Define the real user problem or search intent in plain language.
2. Confirm AQOON can provide a materially useful answer, not a thin keyword page.
3. For public-service facts, identify the responsible authority/provider and verify the current primary source.
4. Make the page answer the question quickly, then explain the next action.
5. Add a natural internal path to deeper help or `/caawi` when relevant.
6. Measure the behavior that matters: qualified visits, starts, contact saves, completions, calls or other defined conversion—not vanity traffic alone.

## Technical checklist

- unique, descriptive title and meta description
- one clear H1 matching page purpose
- self-referencing canonical on indexed pages
- correct `lang`
- crawlable internal links
- sitemap entry for public canonical pages
- no accidental `noindex`
- useful Open Graph data on important shareable pages
- structured data only when it truthfully matches visible content/entity
- mobile speed and readable layout preserved

## Content rules

- No keyword stuffing.
- No doorway pages or city clones without unique verified local value.
- Do not imply AQOON is an authority.
- Do not make eligibility, deadline or benefit claims from old AQOON copy.
- Prefer exact current official pages over authority homepages for factual claims.
- Keep Somali/Finnish wording natural; search terms should fit the sentence rather than distort it.
- Use internal links where they genuinely answer the next question.

## Experiment loop

Search/query or audience pain → useful answer → trusted source → next action → measurable event → review outcome → improve.

`seo/verified-links.json` is a deploy/QA discovery manifest, not the canonical owner of every public-service fact. Canonical factual records and current official sources win when they conflict.
